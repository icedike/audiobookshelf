## Project Overview

Audiobookshelf is a self-hosted audiobook and podcast server built with Node.js and Nuxt.js (Vue 2). It supports streaming audio, multi-user management, progress tracking, metadata management, podcast downloading, and progressive web app (PWA) functionality.

## Architecture

### Server (Node.js/Express)

The server is a classic Node.js Express application with Sequelize ORM for SQLite database management.

**Entry Point**: `index.js` loads configuration (from `dev.js` in development) and starts `server/Server.js`

**Core Components**:
- **Server.js**: Main Express server initialization, middleware setup, and routing
- **Database.js**: Sequelize ORM wrapper with model accessors and initialization logic
- **Auth.js**: Authentication/authorization using Passport.js with JWT strategy
- **SocketAuthority.js**: WebSocket management via Socket.IO for real-time updates
- **Watcher.js**: File system watcher for detecting library changes

**Directory Structure**:
- `server/controllers/`: API endpoint handlers (e.g., LibraryController, PodcastController)
- `server/routers/`: Express route definitions (ApiRouter, HlsRouter, PublicRouter)
- `server/models/`: Sequelize models (Library, LibraryItem, Book, Podcast, User, etc.)
- `server/managers/`: Business logic managers (BackupManager, PodcastManager, CronManager, etc.)
- `server/scanner/`: Library scanning logic (LibraryScanner, BookScanner, PodcastScanner)
- `server/providers/`: External metadata providers (Audible, Google Books, iTunes, etc.)
- `server/libs/`: Third-party libraries and utilities
- `server/utils/`: Helper utilities for file operations, validation, etc.
- `server/migrations/`: Database migration scripts

**Data Flow**:
1. API requests → `server/routers/ApiRouter.js` → controller → manager/model → database
2. WebSocket events managed through `SocketAuthority.js` for real-time updates
3. File system changes detected by `Watcher.js` → trigger library scans via `LibraryScanner`

### Client (Nuxt.js/Vue 2)

The client is a Nuxt.js 2 static site with Socket.IO for real-time communication.

**Configuration**: `client/nuxt.config.js` defines routing, proxying, PWA settings, and build options

**Directory Structure**:
- `client/pages/`: Vue page components (routes auto-generated by Nuxt)
- `client/components/`: Reusable Vue components
- `client/store/`: Vuex store modules for state management
- `client/plugins/`: Nuxt plugins (axios, i18n, utilities)
- `client/players/`: Audio/ebook player components
- `client/layouts/`: Layout templates
- `client/strings/`: Localization files organized by language

**Communication**:
- REST API calls via axios to server endpoints
- Real-time updates via Socket.IO (configured in nuxt.config.js with `nuxt-socket-io`)
- Proxies requests to server in development mode (port 3000 → 3333)

### Database

Uses **SQLite** with **Sequelize ORM**. Database file stored in `CONFIG_PATH/absdatabase.sqlite`.

Key models: Library, LibraryItem, Book, Podcast, PodcastEpisode, User, MediaProgress, PlaybackSession, Author, Series, Collection, Feed

Migration system managed by `MigrationManager` with scripts in `server/migrations/`

## Development Commands

### Initial Setup

For manual setup (without dev container):
1. Create `dev.js` in the project root (see `.devcontainer/dev.js` for template)
2. Install dependencies and build client:
```bash
npm ci
cd client
npm ci
npm run generate
cd ..
```

### Running the Application

**Server only** (serves pre-built client from `client/dist`):
```bash
npm run dev
```
Server runs at `localhost:3333` by default (configurable in `dev.js`)

**Client with live reload** (for active client development):
```bash
npm run dev  # In one terminal - runs server
cd client && npm run dev  # In another terminal - runs client with hot reload at localhost:3000
```

### Testing

**Server tests** (Mocha):
```bash
npm test
```

Run a single test file:
```bash
npx mocha test/path/to/test.js
```

**Client component tests** (Cypress):
```bash
cd client
npm test  # Run all component tests headlessly
npm run test-visually  # Open Cypress UI for interactive testing
```

**Test coverage**:
```bash
npm run coverage
```

### Building

**Build client**:
```bash
cd client
npm run generate
```

**Build for production**:
```bash
npm run prod  # Builds client and starts server
```

**Platform-specific builds**:
```bash
npm run build-win  # Windows executable
npm run build-linux  # Linux packages
```

### Docker

```bash
npm run docker  # Multi-platform build and push
npm run docker-amd64-local  # Local AMD64 build
npm run docker-arm64-local  # Local ARM64 build
```

## Key Technical Details

### Configuration and Environment

- **Development**: Uses `dev.js` for local configuration (paths, ports, binaries)
- **Production**: Uses environment variables or command-line arguments
- **Router Base Path**: Default is `/ai` (configurable but must match this path for subfolder deployments)

### Important Dependencies

- **Server**: express, sequelize, sqlite3, socket.io, axios, ffmpeg (binary dependency)
- **Client**: nuxt 2.x, vue 2.x, tailwindcss 4.x, nuxt-socket-io, axios

### WebSocket Requirements

The application requires WebSocket support. When configuring reverse proxies, ensure WebSocket upgrades are properly forwarded.

### File Processing

- **FFmpeg/FFprobe**: Required for audio processing, metadata extraction, and m4b merging
- **Audio formats**: Streams all formats on-the-fly using HLS (HTTP Live Streaming)
- **Ebook formats**: epub, pdf, cbr, cbz supported

### Library Scanning

The scanner system (`server/scanner/`) automatically detects and processes:
- New/modified files via `Watcher.js`
- Directory structures for books and podcasts
- Metadata from multiple sources (embedded tags, NFO files, OPF files, external providers)

## Testing Strategy

- Server unit tests in `test/server/` using Mocha/Chai
- Client component tests using Cypress for Vue components
- Integration tests for API endpoints
- No E2E tests currently in repository

## Common Workflows

### Adding a new API endpoint:
1. Define route in `server/routers/ApiRouter.js`
2. Create/update controller in `server/controllers/`
3. Add business logic in appropriate manager if needed
4. Update models if database changes required
5. Add migration script if schema changes

### Adding client functionality:
1. Create/update Vue component in `client/components/`
2. Add page in `client/pages/` if new route needed
3. Update Vuex store in `client/store/` for state management
4. Add API calls in component or plugin

### Database migrations:
1. Create migration file in `server/migrations/`
2. Follow naming convention: `v2.x.x-migration-name.js`
3. Test migration both up and down
4. Migrations run automatically on server start
